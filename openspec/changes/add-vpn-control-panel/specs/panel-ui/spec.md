# panel-ui — Delta

## ADDED Requirements

### Requirement: Страницы панели
Панель ДОЛЖНА содержать страницы: Login, Dashboard, Servers, Exits, Sites, Clients, Settings.

#### Scenario: Навигация
- **WHEN** администратор вошёл в панель
- **THEN** в сайдбаре доступны перечисленные разделы, в шапке — статус маршрутизации и кнопка выхода
- **AND** прямой переход по URL сохраняет состояние выбранной страницы (TanStack Router)

### Requirement: Мастер добавления сервера
Панель ДОЛЖНА вести администратора через добавление сервера без ручных подсказок.

#### Scenario: Шаги мастера
- **WHEN** админ нажимает «Добавить сервер»
- **THEN** wizard показывает шаги: (1) SSH-доступ, (2) проверка и предпросмотр, (3) роли и регион, (4) провижининг с прогрессом, (5) результат
- **AND** на шаге 2 можно вернуться и исправить данные, на шаге 4 прогресс приходит через SSE и отображается списком шагов

#### Scenario: Ошибка шага
- **WHEN** шаг провижининга завершился ошибкой
- **THEN** UI показывает конкретный шаг, stderr (без секретов) и кнопки «Повторить» / «Удалить запись»

### Requirement: Вкладка Sites
Панель ДОЛЖНА показывать маршрутизацию в трёх секциях.

#### Scenario: Секции вкладки
- **WHEN** админ открывает Sites
- **THEN** отображаются: (1) «Российские сайты — как есть (не проксируются)» с замком и пояснением о разнице режимов, (2) «Выход по умолчанию» с выбором узла, (3) список site rules с доменами, выбранными выходами и статусом здоровья
- **AND** у каждого правила есть «шестерёнка», открывающая модалку выбора разрешённых выходов (упорядоченный multi-select) с предупреждением о fail-closed

#### Scenario: Пресеты
- **WHEN** админ нажимает «+ Сайт»
- **THEN** доступны пресеты (Anthropic, OpenAI, Google, Telegram, GitHub) и «Свои домены»
- **AND** после выбора выходов правило сохраняется и показывает статус «применено» после успешной ревизии

### Requirement: Гейт обязательного проксирования
Панель ДОЛЖНА блокировать включение маршрутизации без валидного профиля и явно это показывать.

#### Scenario: Профиль не настроен
- **WHEN** выход по умолчанию не выбран
- **THEN** на всех страницах отображается баннер «Проксирование не настроено», кнопка «Применить» неактивна
- **AND** переход из баннера ведёт на Sites с подсветкой обязательного поля

### Requirement: Удаление сервера
Панель ДОЛЖНА требовать явного подтверждения удаления и показывать очистку.

#### Scenario: Подтверждение
- **WHEN** админ нажимает «Удалить сервер»
- **THEN** открывается диалог с вводом имени сервера и списком того, что будет удалено (`~/config/vpn`, юниты, правила firewall)
- **AND** кнопка подтверждения активна только при точном совпадении имени

#### Scenario: Прогресс очистки
- **WHEN** удаление запущено
- **THEN** UI показывает шаги uninstall и результат проверки «каталог удалён»
- **AND** при недоступности SSH предлагает повтор или принудительное удаление записи с предупреждением

### Requirement: QR и ссылки
Панель ДОЛЖНА показывать QR и ссылку клиента.

#### Scenario: Модалка подключения
- **WHEN** админ нажимает «Подключиться» у клиента
- **THEN** модалка предлагает два режима: «Умный профиль (RU напрямую)» — QR на URL подписки с RU-bypass, и «Полный туннель (vless)» — QR на `vless://`
- **AND** доступны копирование ссылки и скачивание `.svg`/`.json`; для узлов без роли entry подключение недоступно с пояснением

### Requirement: Состояния загрузки и ошибок
Панель ДОЛЖНА корректно обрабатывать загрузку, ошибки и пустые состояния.

#### Scenario: Ошибка API
- **WHEN** запрос завершается 4xx/5xx
- **THEN** показывается toast с понятным текстом и возможностью повтора, интерфейс не «ломается»
- **AND** скелетоны отображаются при загрузке, пустые состояния содержат призыв к действию

### Requirement: Лёгкость и производительность
Панель ДОЛЖНА быть лёгкой.

#### Scenario: Бюджет бандла
- **WHEN** собирается production-бандл
- **THEN** начальный JS-gzip не превышает 250 КБ, все страницы грузятся лениво (code-splitting)
- **AND** в зависимостях нет тяжёлых UI-фреймворков (MUI/AntD/Chakra); используется shadcn/ui + Radix

### Requirement: Оформление и доступность
Панель ДОЛЖНА поддерживать светлую/тёмную тему и базовую доступность.

#### Scenario: Тема и клавиатура
- **WHEN** админ переключает тему
- **THEN** выбор сохраняется, контраст соответствует WCAG AA
- **AND** все интерактивные элементы доступны с клавиатуры, модалки удерживают фокус и закрываются по Escape

### Requirement: Язык интерфейса
Интерфейс ДОЛЖЕН быть на русском языке.

#### Scenario: Тексты
- **WHEN** отображается любой экран
- **THEN** подписи, ошибки и подсказки — на русском; технические идентификаторы (домены, ID) — как есть
