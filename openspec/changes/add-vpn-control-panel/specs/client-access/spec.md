# client-access — Delta

## ADDED Requirements

### Requirement: Управление клиентами
Система ДОЛЖНА позволять создавать, переименовывать, отключать и удалять клиентов VLESS.

#### Scenario: Создание клиента
- **WHEN** админ создаёт клиента с именем (например, «iPhone»)
- **THEN** система генерирует UUID v4 и `email`-тег вида `client-<id>@vpn` для учёта статистики
- **AND** клиент добавляется на все entry-узлы без перезапуска Xray (`adu`), desired-state хранится в БД и повторно применяется после рестарта ядра

#### Scenario: Дубликат имени
- **WHEN** админ создаёт клиента с уже существующим именем
- **THEN** запрос отклоняется с ошибкой `name_taken`

### Requirement: VLESS+REALITY ссылка
Система ДОЛЖНА генерировать корректную `vless://` ссылку для выбранного entry-узла.

#### Scenario: Формирование ссылки
- **WHEN** админ открывает карточку клиента для entry-узла
- **THEN** ссылка содержит `uuid`, адрес узла, порт 443, `encryption=none`, `security=reality`, `pbk` (публичный ключ), `sid` (shortId, hex, чётная длина ≤16), `fp=chrome`, `sni` (маскировочный домен), `spx=%2F`, `flow=xtls-rprx-vision` и `type=tcp`
- **AND** параметры собираются через URLSearchParams (без конкатенации), IPv6-адрес — в квадратных скобках, имя узла — во фрагменте после `#`

#### Scenario: Ссылка после смены конфигурации
- **WHEN** REALITY-ключи или маскировочный домен узла изменены
- **THEN** все выданные ссылки пересчитываются и отображаются в новой ревизии

### Requirement: QR-код подключения
Система ДОЛЖНА отдавать QR-код VLESS-ссылки.

#### Scenario: Показ QR
- **WHEN** админ нажимает «Показать QR»
- **THEN** панель показывает QR-код ссылки данного клиента для выбранного entry-узла
- **AND** доступно скачивание `.svg`/`.png` и копирование ссылки

#### Scenario: Сканирование
- **WHEN** клиент сканирует QR в штатном VLESS-клиенте
- **THEN** профиль создаётся и подключение устанавливается без ручного ввода параметров

### Requirement: Отзыв доступа
Система ДОЛЖНА немедленно отзывать доступ отключённого/удалённого клиента.

#### Scenario: Отключение клиента
- **WHEN** админ отключает клиента
- **THEN** пользователь удаляется со всех entry-узлов (`remove user` через Xray API) без перезапуска
- **AND** существующие сессии клиента прекращаются, новые подключения отклоняются

### Requirement: Лимит трафика клиента
Система ДОЛЖНА поддерживать необязательный лимит трафика на клиента.

#### Scenario: Превышение лимита
- **WHEN** суммарный трафик клиента (uplink + downlink) достиг лимита
- **THEN** клиент автоматически отключается на всех узлах, в UI отображается `limit reached`
- **AND** админ может поднять лимит или сбросить счётчик вручную

### Requirement: Статистика по клиенту
Система ДОЛЖНА показывать по клиенту трафик за периоды и текущий статус.

#### Scenario: Карточка клиента
- **WHEN** админ открывает клиента
- **THEN** отображаются суммарный трафик (24 ч / 7 д / 30 д), последняя активность, узлы, где клиент включён, и текущий статус (active/disabled/limit)

### Requirement: Умный профиль с RU-bypass
Система ДОЛЖНА выдавать клиенту профиль, в котором российские домены и IP не проходят через VPN, а зарубежные — проходят.

#### Scenario: Генерация умного профиля
- **WHEN** админ выбирает режим «Умный профиль (RU напрямую)»
- **THEN** система генерирует конфигурацию клиента (sing-box JSON; Clash Meta YAML — по `User-Agent` подписки) с правилами `geosite:category-ru` и `geoip:ru` → `direct`, всё остальное → VLESS+REALITY на entry
- **AND** DNS для RU-доменов резолвится локально, для остальных — через выход

#### Scenario: Импорт по QR/подписке
- **WHEN** клиент сканирует QR с URL подписки
- **THEN** клиент получает профиль с RU-bypass и после подключения российские сайты открываются с обычного российского IP
- **AND** формат ответа выбирается по `User-Agent`: sing-box JSON, Clash Meta YAML, base64-список `vless://` (v2ray); в заголовках `Subscription-Userinfo` (трафик) и `Profile-Title`
- **AND** токен подписки персональный, неугадываемый, доступен без сессии и отзывается вместе с клиентом

### Requirement: Режим полного туннеля
Система ДОЛЖНА сохранять возможность выдать простую `vless://` ссылку.

#### Scenario: Выбор режима
- **WHEN** админ выбирает «Полный туннель (vless)»
- **THEN** отдаются `vless://` ссылка и QR; RU-домены при этом направляются напрямую на entry (не через выходы)
- **AND** UI предупреждает, что RU-трафик в этом режиме идёт через entry-IP, а не напрямую с устройства
