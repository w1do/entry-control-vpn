# Change: VPN Control Panel (MVP)

## Why

VPN сейчас собирается вручную: отдельно VPS, отдельно Xray, ключи REALITY, маршрутизация по доменам, мониторинг и переключение выходов. Нужен один сервис с удобной панелью, который:

- добавляет сервер по SSH и сам разворачивает на нём узел (Xray VLESS+REALITY) и подключает его к панели;
- позволяет задавать «выходы» по регионам (например, Сингапур, США) и проксировать зарубежные сайты на выбранный выход;
- не проксирует российские сайты вообще — они открываются напрямую с российского IP, как без VPN; зарубежные идут через выбранный выход, а заданный сайт (например, Anthropic) — только через явно разрешённые выходы;
- выдаёт VLESS-ссылку и QR для подключения;
- показывает трафик, подключения, ошибки и аптайм;
- при удалении сервера уничтожает всё, что на нём было настроено (единый корень `~/config/vpn`).

Деплой — в Dokploy; панель — лёгкая (React + TanStack + shadcn/ui).

## What Changes

Greenfield-сервис из четырёх частей:

1. **Backend / control-plane** — FastAPI: серверы, выходы, сайты, клиенты, компиляция конфигов Xray, jobs по SSH, сбор метрик, аутентификация.
2. **`vpn-agent`** — Go-демон на узле: приём конфигурации, атомарное применение, сбор статистики Xray, репорт в панель.
3. **Frontend** — React 19 + TanStack Router/Query + shadcn/ui: login, dashboard, servers, exits, sites, clients.
4. **Deployment** — docker-compose для Dokploy: один контейнер приложения (static SPA + API) + том для SQLite.

Существующие `openspec/specs/` отсутствуют — все capability добавляются целиком.

## Impact

- **Новые файлы:** `backend/`, `frontend/`, `agent/`, `deploy/`, `openspec/changes/add-vpn-control-panel/`.
- **Инфраструктура:** Dokploy-проект, домен, TLS через Traefik; управляемые VPS (Linux, root/sudo, systemd).
- **Секреты:** `ADMIN`, `PASSWORD`, `ENCRYPTION_KEY`, `SECRET_KEY` в `.env` Dokploy; SSH-доступы шифруются в БД.
- **Внешние зависимости:** Xray-core (фиксированная версия), geosite/geoip-датасет, Go-тулчейн для сборки агента.

## Non-goals (MVP)

- Мультитенантность и роли; биллинг; подписки/оплаты.
- Клиентские приложения под iOS/Android/Windows — используются готовые VLESS-клиенты по ссылке/QR.
- Автоматический подбор/покупка VPS и прокси.
- Поддержка не-Linux узлов.
- Тонкая политика по каждому IP/порту (только домены/geosite/geoip).

## Success criteria

1. Чистый VPS добавляется по SSH, через 2–4 минуты узел в статусе `online`, QR ведёт на рабочий VLESS+REALITY.
2. Российские сайты не проксируются: в умном профиле открываются напрямую с российского IP (не покидают устройство), в vless-режиме — не уходят ни на один выход; зарубежные идут через выбранный exit; сайт с явным allowlist не использует другие выходы ни при каких условиях (проверяется тестом конфига).
3. Остановка exit-узла не отправляет трафик разрешённого сайта ни на другой выход, ни напрямую — соединение блокируется (fail-closed), панель показывает инцидент.
4. Удаление сервера оставляет на нём только системный минимум: `~/config/vpn` отсутствует, юниты `vpn-agent`/`xray` удалены, правила firewall сняты.
5. Дашборд показывает трафик за 24ч/7д, активные соединения, ошибки и uptime % по каждому узлу с задержкой не более 60 секунд.
6. Панель не позволяет включить маршрутизацию, пока не задан выход по умолчанию и не пройдена валидация профиля.
7. Деплой в Dokploy одной compose-конфигурацией; `/healthz` отвечает 200; после рестарта контейнера состояние сохраняется.
8. Внешний резидентский выход проверяется по фактическому IP/стране; при подмене гео или недоступности трафик сайтов с этим выходом блокируется, а не уходит через другие выходы.

## Risks & mitigations

| Риск | Митигация |
|---|---|
| REALITY-ключи/SSH-креды утекают | Шифрование в БД (Fernet), секреты не логируются, генерация ключей только на бэкенде |
| Узел остаётся «грязным» после удаления | Всё в `~/config/vpn`, uninstall удаляет каталог + юниты + nft/ufw-правила; отчёт job'а |
| Ошибка применения конфига роняет VPN | Двухфазное применение (validate → swap → restart → health), авто-rollback и блокировка применения при провале |
| Медленная/нестабильная SSH-связь | Idempotent-шаги, ретраи с backoff, статус `degraded`, повтор из UI |
| Детект IP-репутации у целевых сервисов | Exit-узлы по регионам + возможность внешнего upstream-прокси (roadmap); проверка exit-IP в health-check |
| Потеря доступа к панели | Агент автономен: последняя конфигурация продолжает работать; вход только через один админ-аккаунт |

## Зависимости

- Активные change'и: нет.
- Внешние: Xray-core 26.11.x (пиннится; SS-2022 deprecated), geodata (XTLS/Xray-rules-dat или Loyalsoldier, sha256-пиннинг), Go 1.23, Node 22, Python 3.12.
